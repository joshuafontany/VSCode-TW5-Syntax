# ── A STATE TOGGLE NEVER TAKES A COLOUR AWAY ─────────────────────────────────
#
# TiddlyWiki carries pragmas that change what its parser reads: `\rules except rules` turns the
# rules pragma off, `\rules only table` leaves one rule standing, `\parsermode inline` reads the
# rest of the tiddler as one inline run. After such a line the parser refuses constructs it would
# otherwise build, and it refuses them for the rest of the tiddler.
#
# This grammar colours them anyway, and the ruling stands on what colouring DOES. At design time a
# reader wants to see the base language: that a line IS a rules pragma, that a run IS bold, whatever
# a toggle further up has switched off. The operator holds the tiller for render time — they wrote
# the toggle, they know what it does, and they can read its effect from the toggle itself. A grammar
# that greyed out everything below a `\rules except` line would hide the language from the person
# editing it, to describe a state they authored.
#
# So a construct the grammar reads and a toggle disabled stands here, and the divergence gate reads
# it as a ruling rather than as overreach.
meta.directive.rules                          # the rules pragma keeps its colour after a toggle that disabled it — a reader edits the base language, and the toggle above says what the renderer will do
keyword.control.directive.rules               # the same reading, for the directive's own keyword
keyword.operator.only                         # the same reading, for the only operator inside one
keyword.operator.except                       # the same reading, for the except operator inside one
tiddlywiki5.tw:punctuation.definition.directive  # the same reading, for the backslash opening a rules pragma the fixture disabled above
tiddlywiki5.tw:variable.parameter                # the same reading, for the rule names such a pragma lists

# ── THE STRUCTURAL PATTERN CARRIES THE COLOUR ────────────────────────────────
#
# A shortcut reads `<% keyword ... %>`, and the keywords this TiddlyWiki ships come from one rule
# module — conditional.js wants `if`, and the family closes on `endif`. A wiki can carry more: a
# tiddler or a plugin registers a wikirule of its own, and the shortcut a reader writes tomorrow
# stands unknown to the parser booted here today.
#
# So the grammar colours the STRUCTURE — the `<%`, the `%>`, the keyword between them — and names an
# unrecognised keyword as unrecognised rather than refusing the shape. A reader looking at
# `<% iff %>` learns that they wrote something shortcut-shaped and that this wiki does not answer to
# it; a reader looking at a shortcut their own plugin defines sees it read as one.
#
# `meta.link.wikilink` above stands on the same reading, for a rule TiddlyWiki ships and disables.
# This names the other direction: a rule a wiki may add.
#
# The cost stands measured and stands accepted: prose that NAMES the syntax — "delimited with <% and
# %>" — colours as a shortcut across the words between. A sentence about the language reads as the
# language.
meta.shortcut                                 # a wiki or a plugin may register a shortcut this TiddlyWiki never shipped, so the structural pattern carries the colour and the keyword names itself
keyword.control.shortcut.unrecognized         # the reading that says so: shortcut-shaped, and no rule here answers to this keyword
punctuation.definition.tag.shortcut           # the marks that open and close one
newsyntax.tw:punctuation.definition.tag       # a sentence naming the syntax carries the marks it names
tiddlywiki5.basic.tw:punctuation.definition.tag  # the same sentence, in the fixture that quotes it
tiddlywiki5.tw:punctuation.definition.tag        # and again

# ── THE MARK CARRIES THE COLOUR, WHATEVER THE PARSER MAKES OF IT ─────────────
#
# The same reading, in two fixtures that exercise degenerate forms on purpose. Each ruling names ONE
# fixture, so the shape still reports anywhere else and this gate keeps its teeth.
#
# THREE STYLE OPENERS IN A ROW, AND WHAT STANDS ABOVE THEM. `@@color:blue;`,
# `@@background-color:red;`, `@@.class1.class2` on consecutive lines: this grammar reads three block
# openers, and so, on its own, does TiddlyWiki — it accumulates all three into ONE element carrying
# style="color:blue;background-color:red;" class="class1 class2". Measured on those three lines
# alone, the class names read as BUILT and nothing diverges.
#
# What diverges comes from ABOVE them. The fixture opens with a bare `@@` pair — an empty style block
# — and after it the parser reads the three openers as a paragraph: `color:blue;` arrives as plain
# text, `background-color:red;` as an inline style run, `.class1.class2` as plain text again. The
# same three lines, one empty block earlier in the tiddler, and the marks mean something else.
#
# No rule in this grammar can see that. A TextMate rule fires on a line without knowing which block
# boundary a construct above it consumed, and the reading it would need — did an empty style block
# eat the boundary — stands in the parser's state rather than in the text. So the marks carry the
# colour, and the author reads what they wrote.
#
# AN IMAGE WITH A BLANK SOURCE. `[img[ ]]` carries every mark an image carries and no source between
# them. TiddlyWiki refuses it; the marks still say what the author reached for, and a reader looking
# at a coloured image shape with nothing inside it can see what the shape wants.
#
# The source may cross a line, and both readers follow it: `[img[pic` on one line and `.png]]` on the
# next builds an image node upstream and colours as one here, tooltip form included. Measured, so a
# reader wondering whether the mark stops at the line end can stop wondering. What TiddlyWiki refuses
# stands narrower than that — a source that carries nothing at all.
tiddlywiki5.basic.tw:punctuation.definition.style.markup      # three style openers in a row: the marks carry the colour, and TiddlyWiki reads the second and third as content of the first
tiddlywiki5.basic.tw:punctuation.definition.entity.css        # the class marks inside such an opener
tiddlywiki5.basic.tw:entity.other.attribute-name.class.css    # and the class names beside them
tiddlywiki5.basic.tw:markup.bold                              # a bold run on the line after the closing mark, which the parser reads as content of the run above it
tiddlywiki5.basic.tw:punctuation.definition.markup.begin.bold # the marks opening that run
tiddlywiki5.basic.tw:punctuation.definition.markup.end.bold   # and closing it
tiddlywiki5.tw:punctuation.definition.style.markup            # the same three openers, in the fixture that carries every construct
tiddlywiki5.tw:punctuation.definition.entity.css              # the same reading
tiddlywiki5.tw:entity.other.attribute-name.class.css          # the same reading
tiddlywiki5.tw:markup.bold                                    # the same reading
tiddlywiki5.tw:punctuation.definition.markup.begin.bold       # the same reading
tiddlywiki5.tw:punctuation.definition.markup.end.bold         # the same reading
